## 2. Feasibility gate (RPS Casebook F(−1)…F7, applied before design freeze)

**F(−1) Decision relevance.**
- Positive branch (Arm 2 > Arm 1 by ≥ SESOI, §7): `H_RS` is retained *in the declared family and difficulty range*; the relational-memory thread may cite one controlled measurement in favour of externalized relational state; a follow-up cell (propagation arm) becomes decision-relevant.
- Negative branch (CI excludes effects ≥ SESOI): `H_RS` is withdrawn or narrowed *in the declared scope*; organization alone is recorded as insufficient; the architecture thread's assumption that propagation is required is retained, unstrengthened.
- Inconclusive (CI spans zero and SESOI): recorded as such; no host sentence changes; a larger or harder campaign is a separate cell.
- Excluded from counting: any refinement of the relational-memory vocabulary, tagging, or grammar. Framework self-corrections do not satisfy F(−1).

**F0 Semantic slot.** Fixed: model identity, execution profile, puzzle instance, clue order, query wording, output contract. Changed: representation of the clue set only. Slot: representational. Arm 3 (automatic propagation) changes computation and occupies a different slot; it is not part of this cell.

**F1 Forced outcomes (derived before running).**
- An exhaustive oracle solves every generated instance by construction — it is a ground-truth instrument, not an arm.
- `PROP-RS-0` defines depth; exhaustive enumeration defines truth. No claim that `PROP-RS-0` establishes global satisfiability is made. Any future Arm-3 result that merely confirms behaviour guaranteed by that propagator's explicitly implemented rules is regression, not evidence. Not in this cell.
- Nothing forces Arm 2 ≥ Arm 1. The model reads both renderings; more structure may help, be neutral, or hurt (longer input, unfamiliar layout). This is why the cell is an occupancy discriminator.
- Predicted outcome, stated for the record: with the frozen primary subject (`gpt-5.6-terra`) at $n\le5$ the family is expected to sit at ceiling and $\Delta_{\rm RS}\approx0$ (F2 failure). The calibration step exists to detect this before the main campaign.

**F2 Reachability.** Threshold-dependent by construction: the effect can only appear where Arm-1 accuracy leaves the ceiling. Calibration (§8.1) estimates Arm-1 accuracy across $n\in\{3,\dots,9\}$ and depth; the main family is chosen where pooled Arm-1 accuracy lies in $[0.30,0.80]$. If no such region exists at the maximum generated difficulty, STOP.

**F3 Occupancy.** The generator guarantees both target states are populated per stratum (exactly one global solution / exactly two global solutions). Ambiguous instances are generated by construction (§4.3), not by rejection sampling on failures. Candidate entities are never deduplicated by descriptor equality at encoding: two handles with identical clue neighbourhoods remain two handles.

**F4 Controls.** The oracle is `REGRESSION`. The two serializers' round-trip equality is an admission test, not evidence. The only discriminating comparison is Arm 1 vs Arm 2, paired on identical instances.

**F5 Carrier completeness.** Every instance is rendered whole: all clues, all handles, all items. No sub-graph, no query-dependent subset, in either arm.

**F6 Estimator semantics.** Accuracy, false-certainty rate, token counts and depth labels are post-hoc run classifications and instance metadata. None is fed back into any prompt or representation.

**F7 Inference assumptions.** Depth labels are defined relative to a named propagator (§4.2). "Unique" and "ambiguous" are defined by exhaustive enumeration, not by propagator fixed point. No claim of the form "path-consistency fixed point ⇒ global consistency" is made anywhere in the cell.

**Post-hoc rule.** Any analysis not preregistered here is `[EXPLORATORY]` and may not close the GAP.

## 4. Puzzle family (declared, frozen at admission)

**4.1 Structure.** $n$ persons, $n$ items, one-to-one assignment. Handles are drawn from disjoint neutral name lists (no real-person names, no culturally loaded items). Identifiers: `puzzle_id` = sha256(canonical clue multiset); `trial_id` = sha256(puzzle_id, target). Both arms of a pair share `trial_id`. Quarantine between pilot and main sample operates on `puzzle_id`, so the same puzzle cannot re-enter under a different target.

**4.2 Clue atoms (canonical source of truth).** Two relations only in v0:

```
id        C<k>
relation  EQUAL | NOT_EQUAL
termini   (Person, Item)
```
`EQUAL P I` — P has I. `NOT_EQUAL P I` — P does not have I. Together with the declared one-to-one rule these generate cascaded elimination and depths 1…4 without any further clue type. `DIFFERENT` (tautological under one-to-one) and `CHAIN` (not semantically sharp for $n>2$) are removed from v0; either may be introduced by a later cell with its own propagator semantics.

**Depth label (`PROP-RS-0`, synchronous-wave semantics, R1-only — amended v0.3.2).** State = the $n\times n$ admissibility board. Round 0 applies every clue atom to the initial board. One round = one simultaneous wave computed from the board *at the start of the round*, applying the single rule **R1**: a person with exactly one admissible item removes that item from every other person. Consequences derived within a round are **not** re-applied until the next round. $d$ = the first round after which the target row is a singleton (unique instances) or the round of the last change before the fixed point (ambiguous instances). Reproducible by construction; recorded per instance. *Amendment note (F1):* v0.3.1 also applied R2 (an item admissible for exactly one person fixes that person). Under R1+R2 a unique-target depth $d$ requires $n\ge 2d$, leaving the declared 24-strata family instantiable only for $n\in\{8,9\}$; under R1-only the bounds are unique $n\ge d+1$, ambiguous $n\ge d+2$, and all strata are populated for $n\ge6$. R2 remains available in the implementation only as a non-default evaluation option and is never used for labelling. Depth is a difficulty coordinate only; truth is defined by exhaustive enumeration.

**4.3 Target state.** The query names one person (the target). The generator produces, per stratum, instances with exactly one global solution, and instances with exactly two global solutions that differ on the target (ambiguity is constructed by omitting the clue that would separate two symmetric completions, then verified by enumeration).

**4.4 Strata.** $n\in N_{\rm main}$ (chosen at calibration, three values) × $d\in\{1,2,3,4\}$ × target state ∈ {unique, ambiguous} = 24 strata; trials per stratum = $N/24$ with $N$ from §7 (≥ 50).

## 5. Arms

**5.1 Arm 1 — flat state (`FLAT-v0`).** The canonical clue records in instance clue order, one per line, no grouping, no index:
```
C1 NOT_EQUAL Alice Steak
C2 EQUAL Bob Broccoli
C3 NOT_EQUAL Alice Broccoli
```

**5.2 Arm 2 — relationally organized state (`RM-v0`).** The canonical clue table **once**, byte-identical to Arm 1's block, followed by an adjacency index that repeats **clue IDs only**, in canonical handle order (order of first appearance in the clue list — never target-first):
```
CLUES
C1 NOT_EQUAL Alice Steak
C2 EQUAL Bob Broccoli

INDEX
Alice: C1
Bob: C2
Steak: C1
Broccoli: C2
```
No clue body appears more than once in either arm (A6). The prompt preamble states in one sentence, identical across arms, that the index lists clue IDs per handle.

**5.3 Forbidden in Arm 2** (checked mechanically, §6): domain intersection; derived candidate sets; composition; residuals; inferred edges; entity deduplication; constraint propagation; query-based pruning or ordering; any content not traceable one-to-one to a clue record or to the handle index itself.

**5.4 Prompt frame (`FRAME-v0`, frozen v0.3.2).** One instruction block, identical across arms, placed before the state; the query follows the state. Frozen by hash: `FRAME_SHA256 = a70cd833982abe491d244b3a8a6c714e30cd8f1affa13ad4621e320169885a72` over `FRAME_TEMPLATE + "\n" + QUERY_TEMPLATE` in `ai_lab/experiments/relational_state/render.py`; the campaign manifest records this hash and the runner refuses to start if it differs. Literal template (`{persons}`, `{items}`, `{target}` are the only substitutions):

```
You are given a logic puzzle.
Persons: {persons}.
Items: {items}.
Rules: every person has exactly one item and every item belongs to exactly one person.
Clue lines have the form: <clue-id> <RELATION> <Person> <Item>, where EQUAL means the person has the item and NOT_EQUAL means the person does not have the item.
If an INDEX section is present, each line lists, for one person or item, the ids of the clues that mention it; an index entry is a reference to a clue, not an additional clue.
Answer with a single JSON object and nothing else, of the form {"status": "unique" | "ambiguous" | "inconsistent", "answer": ["<item>", ...]}. Use "unique" with one item when exactly one item is possible for the queried person, "ambiguous" with all possible items when more than one is possible, and "inconsistent" with an empty list when the clues admit no assignment.

Question: which item belongs to {target}?
```

**5.5 Output contract.** JSON only:
```
{"status": "unique" | "ambiguous" | "inconsistent", "answer": ["<item>", ...]}
```
No explanation requested. Parsing is strict; the first JSON object in the response is scored.

## 6. Admission invariants (every instance, automated, before any provider call)

Let $C$ be the canonical clue multiset of an instance.
$$
\begin{aligned}
A1:&\ Decode(Render_1(C)) = C\\
A2:&\ Decode(Render_2(C)) = C\\
A3:&\ Decode(Render_1(C)) = Decode(Render_2(C))\\
A4:&\ InferenceDerivedFacts(Render_2(C)) = \varnothing
\end{aligned}
$$
$InferenceDerivedFacts(\cdot)$ is the set of rendered lines that are neither a verbatim clue line nor a line of the deterministic ID-only adjacency index. RM-v0 may add **structural indexing** derivable from the source clues — that index is the treatment — but no **semantic entailment**; the cell tests *organization/indexing without semantic inference*, not the absence of all computation. A4 therefore excludes intersection, candidate elimination, composition, residual evaluation, inferred edges, deduplication/gluing, query-specific pruning or ordering, and any transformation that narrows admissible state beyond what one source clue states individually. An instance failing any invariant is excluded and the exclusion logged with the failing invariant. **Single entry point (v0.3.2):** `equivalence.admit_instance(puzzle)` enforces A1–A6 and query independence together and returns the named failures; the runner calls it before every provider call and no other path admits an instance.

**A6 (clue lexical multiplicity).** Every source clue body occurs exactly once in each rendering; only clue IDs may recur (in the index). Enforced per instance. This removes repetition-as-emphasis as a rival explanation of any Arm-2 effect.

**A5 (degenerate-identity guard).** Two independently generated handles remain two handles even when their visible clue neighbourhoods are identical. No generator, canonicalizer or serializer may perform $R_{uv}=I \Rightarrow Glue(u,v)$. Enforced by a test that constructs two handles with identical descriptors and asserts both survive rendering and decoding with distinct identities.

Token counts $L_1, L_2$ are recorded per instance; no length bound is imposed (relation-heavy instances necessarily render longer in Arm 2); a length-adjusted analysis is secondary (§7).

**Query independence.** The query names the target but alters nothing in either rendering: no reordering, no pruning, no emphasis. Enforced by a test that renders the same instance under every possible target and asserts byte-identical state blocks.

## 7. Endpoints and analysis (frozen)

- **Primary:** $\Delta_{\rm RS} = \mathrm{Acc}_{\rm Arm2} - \mathrm{Acc}_{\rm Arm1}$, pooled over the 24 strata. Correct = status matches oracle and answer set equals the oracle's $\Omega_q$. Paired design.
- **Adjudication by confidence interval.** Paired difference of proportions $\hat\Delta=(b-c)/N$ with $b$ = pairs Arm-2-correct/Arm-1-wrong, $c$ = the reverse. CI method, fixed: **paired Wald interval**, $\hat\Delta \pm z\,\sqrt{(b+c)-(b-c)^2/N}\,/\,N$, no continuity correction, one deterministic routine in the scorer. Adjudication against the SESOI $\delta$:
  - POSITIVE: lower bound $\ge\delta$;
  - NEGATIVE: upper bound $<\delta$;
  - otherwise INCONCLUSIVE (continue to the next stage if one remains, else final INCONCLUSIVE).
  McNemar's test against zero is reported as a descriptive statistic and does not adjudicate.
- **SESOI $\delta = 0.03$** (operator-owned, frozen). **Power design alternative $\Delta_{\rm alt}=2\delta=0.06$:** the campaign is designed for ≈80% power to classify POSITIVE when the true Arm-2 advantage is 6 pp, while requiring evidence that the advantage exceeds 3 pp. Sample size therefore uses $(\Delta_{\rm alt}-\delta)=0.03$ in the denominator: $N_{\rm req}=\lceil q\,(z^{\rm sizing}_{.975}+z^{\rm sizing}_{.80})^2/(\Delta_{\rm alt}-\delta)^2\rceil$ with the **sizing constants frozen at two decimals, $z^{\rm sizing}_{.975}=1.96$, $z^{\rm sizing}_{.80}=0.84$** (v0.3.2, F3; so $q=0.30\to2616=N_{\max}$ is intentional), $q=(b+c)/N$ from the pilot, direction-blinded, rounded up to a multiple of 24. The sequential CI and spending routine use their own full-precision constants. $N_{\min}=1200$, $N_{\max}=2616$. **STOP** if $N_{\rm req}>N_{\max}$ (insufficient budget for preregistered power; terminate or amend *before* the pilot's arm direction is displayed).
- **Staged execution with repeated confidence intervals (operator request).** The main campaign runs in balanced blocks of 240 trials (10 per stratum, 480 calls), with a final balanced partial block when $N_{\rm req}$ is not a multiple of 240 (every block is a multiple of 24, so stratum balance is preserved; e.g. $2616 = 10\times240 + 216$ — corrected in v0.3.2, F4). Looks are permitted only at the preregistered stage boundaries: after blocks 3, 6, 9 and at $N_{\rm req}$, restricted to those $\le N_{\rm req}$ (so $N_{\rm req}=1200$ gives looks at 720 and 1200; $N_{\rm req}=2616$ gives 720, 1440, 2160, 2616).
  - **Spending time.** For this cell, spending time is defined prospectively as $t_k = n_k/N_{\rm req}$. Because every completed full block has identical stratum composition, trial fraction is used as the planned information proxy; no data-dependent re-timing occurs.
  - **Boundary family — one rule for every schedule.** Lan–DeMets O'Brien–Fleming-type alpha spending, $\alpha(t)=2\,[1-\Phi(z_{1-\alpha/2}/\sqrt{t})]$, $\alpha=0.05$, two-sided. After $N_{\rm req}$ is frozen (§8.2), a tested deterministic routine receives exactly the frozen $t_k$ values and computes the sequential critical values $z_k$ recursively (multivariate-normal recursion over the correlated increments) **before stage 1 starts**; the $z_k$ are written into the campaign manifest. No hard-coded multipliers are used operatively; the classical four-look O'Brien–Fleming values may appear in a test fixture only, labelled as a reference case.
  - **Adjudication at a look.** The paired-Wald interval of the primary endpoint is formed with $z_k$ in place of $z_{.975}$ and the POSITIVE / NEGATIVE / INCONCLUSIVE rules of this section apply unchanged; INCONCLUSIVE means continue. Between looks, only direction-blinded quantities ($b+c$, accuracy pooled over arms, token counts) may be displayed.
  - **Finite-sample check (zero-API, before any provider call).** Lan–DeMets spending targets two-sided familywise $\alpha=0.05$ for a Gaussian statistic with known information; the implemented statistic is a paired-Wald statistic with estimated variance. Therefore the exact implemented procedure (block structure, look schedule, spending routine, paired-Wald CI, both stopping rules) is simulated at the boundary case $\Delta=\delta=0.03$ over the preregistered grid $q\in\{0.05,0.10,0.20,0.30,0.40\}$ and every attainable look schedule ($N_{\rm req}\in\{1200,1752,2616\}$ and the schedules implied by the $q$ grid), $\ge 20{,}000$ replications per cell with a fixed seed. Pass criterion: $P(\text{ever classify POSITIVE or NEGATIVE incorrectly at } \Delta=\delta)\le 0.05+\epsilon$ with $\epsilon=0.01$, in every cell. Failure is a **STOP**: amend the statistical routine before provider execution. The claim made is therefore: *Lan–DeMets spending targets $\alpha=0.05$; zero-API simulation verifies the finite-sample behaviour of the implemented paired-Wald approximation before provider execution* — not exact control by construction.
  - **Closure.** Stopping early for POSITIVE or NEGATIVE at a look is a valid closure. Stopping for any other reason (budget, operator decision) closes the cell INCONCLUSIVE at the last completed look and is recorded as such. Extending beyond $N_{\max}$ after any look is not permitted within this cell; it is a new cell with its own preregistration.
- **Secondary 1 (trend):** logistic model on paired correctness with arm × depth interaction; reported, not adjudicating.
- **Secondary 2 (false certainty):** $FCR_a = P(|\hat\Omega_q|=1 \mid |\Omega_q|=2)$ per arm; paired CI as above; reported.
- **Secondary 3 (cost):** $\Delta L = L_2 - L_1$ and output-token difference; accuracy per input token reported.
- **Handling:** unparseable output = incorrect in the primary analysis; sensitivity analysis excludes them. `inconsistent` on this family = incorrect (false-alarm rate reported). Provider errors retried once, then the pair is missing and excluded with the count reported.

## 8. Execution sequence and STOP conditions

**8.0 Zero-API implementation first.** Generator, oracle, depth labeller, both serializers, decoder, admission auditor (A1–A6), scorer, the Lan–DeMets spending routine, the finite-sample simulation check (§7) and the query-independence test are implemented and green before `runner.py` exists. The runner is the only module that invokes a provider, and it is gated behind 8.1. Provider tokens are not a debugging tool.


**8.1 Calibration (non-evidential).** Arm 1 only, 20 puzzles per populated $(n,d)$ — **10 unique + 10 ambiguous** — where each count means 10 *distinct* puzzles; if a finite stratum contains fewer than 10 distinct admissible puzzles, the stratum is exhausted, `requested` and `realized` are recorded, and calibration proceeds; such a shortfall does not alter main-family eligibility (v0.3.3, F7). A consecutive triple is eligible only if every main stratum $(n, d\in\{1..4\}, \text{state})$ is populated (§4.2: $n\ge6$), $n\in\{3,\dots,9\}$, $d\in\{1,\dots,6\}$ where the generator can populate. Output: Arm-1 accuracy surface. **Deterministic selection rule:** among consecutive triples $(n,n+1,n+2)$ whose pooled Arm-1 accuracy lies in $[0.30,0.80]$ (an engineering discrimination window: far enough from both ceiling and floor for a paired effect of size $\delta$ to be observable), select the triple whose pooled accuracy is nearest 0.55; ties choose the smaller $n$. Window and centre are operator-approved values, not derived. **STOP** if no eligible triple exists (report the surface; changing the subject model is a plan amendment, not a result). **Consequence of a second STOP (v0.4):** if the amended subject's calibration also finds no eligible triple, the cell ends; the PLAN closes as *completed-with-calibration-STOP* and **GAP-0009 remains open** — a ceiling before the pilot yields no controlled evidence of the Arm-1/Arm-2 effect, which is a different outcome from the INCONCLUSIVE closure of §7 (a paired campaign whose interval fails to resolve the SESOI). No judgment call occurs after seeing the surface.

**8.1a Execution order (all stages).** Trials are never run as all-Arm-1-then-all-Arm-2. Trial order is a deterministic shuffle from a recorded `campaign_seed`. For each trial the two arms run back-to-back in fresh independent contexts; arm order is A→B if the SHA-256 of `trial_id` has even low byte, B→A otherwise (balanced, frozen, reconstructible). Provider drift therefore affects both arms of a pair nearly equally.

**8.2 Pipeline pilot (non-evidential).** 10 puzzles per stratum, both arms, on $N_{\rm main}$. Verifies generator occupancy, depth labels, oracle classification, A1–A6, scorer, capture, and produces the discordance estimate $q$ for §7. **Blinding procedure:** the runner (1) computes $b+c$, (2) computes $N_{\rm req}$, the look schedule $t_k$ and the Lan–DeMets critical values $z_k$, (3) writes them into the campaign manifest and hashes it, and (4) only then unlocks display of the pilot's arm-direction result. These 240 puzzles are quarantined from the main sample by `puzzle_id`.

**8.3 Main campaign.** $N_{\rm req}$ trials from §7 ($1200\le N\le2616$), $2N$ calls, primary subject only, execution order per 8.1a, run in balanced blocks of 240 trials (final balanced partial block when necessary) with adjudication only at the preregistered looks using the manifest-frozen $z_k$. Every stage JSONL is hashed on completion and its digest entered in the campaign manifest before the next stage starts. Analysis exactly as §7.

**8.4 Replication (separate, smaller).** `claude-sonnet-5`, 10 per stratum, after the primary closes; filed as a rider.
